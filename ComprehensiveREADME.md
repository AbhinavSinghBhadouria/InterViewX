# InterviewX 🎤🤖

**InterviewX** is a modern, AI-powered interview practice and career development platform built with **Next.js**, **TypeScript**, **VAPI**, and **Inngest Agent Kit**.  
It enables users to conduct realistic mock interviews, receive AI-generated feedback, build professional resumes with AI improvements, take technical assessments, get personalized career guidance from an AI agent, access industry insights and salary data, and manage their entire job preparation journey — all within an intuitive and responsive web interface.

---

## 🚀 Project Overview

InterviewX provides a complete end-to-end interview simulation and career development experience, integrating:

- **AI Interviewer** powered by the **VAPI Voice/Chat SDK**
- **AI Career Chat Agent** using **Inngest Agent Kit** for personalized career guidance
- **Advanced Resume Builder** with live preview, AI improvements, and export to PDF/DOCX
- **Multiple Resume Management** - create and manage unlimited resumes
- **Technical Assessments** with AI-generated questions and personalized feedback
- **Industry Insights Dashboard** with real-time salary data, market trends, and growth analytics
- **User authentication** with multiple providers and persistent sessions
- **Payment Integration** with Stripe for premium features
- **Dual-database architecture** for secure authentication and application data
- **Modern UI** built using **React 19 + Tailwind CSS 4**
- **Server-side rendering** and API routes via **Next.js App Router**
- **Background Jobs** with Inngest for scalable AI operations

It is designed for **students, job seekers, and professionals** looking to improve communication skills, structured answering, interview readiness, and career development.

## 🏗️ Architecture Overview

### Dual-Database Architecture

InterviewX uses a **dual-database architecture** to separate authentication concerns from application data:

```
┌─────────────────────────────────────────────────────────────┐
│                    NextAuth (Authentication Layer)          │
│                                                             │
│  ┌──────────────────────────────────────────────────────┐   │
│  │  Session Management (JWT Strategy)                    │  │
│  │  - Stores user._id (MongoDB ObjectId) in JWT token   │   │
│  │  - Session contains: _id, email, name                 │   │
│  └──────────────────────────────────────────────────────┘   │
└───────────────────────┬─────────────────────────────────────┘
                        │
                        │ session.user._id (MongoDB ID)
                        │
        ┌───────────────┴───────────────┐
        │                               │
┌───────▼────────┐              ┌───────▼────────┐
│   MongoDB      │              │  PostgreSQL    │
│  (Auth Data)   │              │  (Neon DB)     │
│                │              │                │
│ • Users        │              │ • User Profiles│
│ • Sessions     │              │ • Resumes      │
│ • Accounts     │              │ • Assessments  │
│ • Verifications│              │ • Chats        │
│                │              │ • Messages     │
│                │              │ • Experience   │
│                │              │ • Education    │
│                │              │ • Skills       │
│                │              │ • Industry Data│
└────────────────┘              └────────────────┘
        │                               │
        │                               │
        └───────────┬───────────────────┘
                    │
            authUserId (Foreign Key)
            Links MongoDB user to PostgreSQL user
```

### Authentication Flow

1. **User Authentication**:
   - User signs in via Credentials, Google, or GitHub
   - NextAuth validates credentials and creates/updates user in MongoDB
   - MongoDB Adapter stores user, session, and account data

2. **Session Creation**:
   - NextAuth creates a JWT token containing:
     - `_id`: MongoDB user ID (ObjectId as string)
     - `email`: User email
     - `name`: User name
   - Token is stored in the session

3. **Application Data Access**:
   - Server actions extract `session.user._id` (MongoDB ID)
   - This ID is used as `authUserId` to query PostgreSQL via Prisma
   - PostgreSQL User model has `authUserId` field that references MongoDB user ID
   - This creates a bridge between the two databases

## 🔐 Authentication & Session Management

### NextAuth Configuration

NextAuth is configured in `src/app/api/auth/[...nextauth]/options.ts` with the following setup:

#### Providers

1. **Credentials Provider**:
   - Email/password authentication
   - Password verification using bcrypt
   - Direct MongoDB query for user lookup

2. **Google OAuth Provider**:
   - OAuth 2.0 flow with Google
   - Automatic user creation via MongoDB Adapter

3. **GitHub OAuth Provider**:
   - OAuth 2.0 flow with GitHub
   - Automatic user creation via MongoDB Adapter

#### Session Strategy

- **Strategy**: JWT (JSON Web Token)
- **Token Storage**: Contains MongoDB user ID, email, and name
- **Session Callbacks**:
  - `jwt`: Transforms user data into token payload
  - `session`: Adds token data to session object

#### MongoDB Adapter

- Uses `@auth/mongodb-adapter` to automatically manage:
  - User accounts in MongoDB
  - Sessions
  - OAuth account linking

### How Session Data is Used

#### 1. Extracting User Information from Session

In server actions and API routes, user information is extracted from the session:

```typescript
import { getServerSession } from "next-auth";
import { authOptions } from "../app/api/auth/[...nextauth]/options";

const session = await getServerSession(authOptions);

if (!session?.user?._id) {
  throw new Error("Unauthorized");
}

// MongoDB user ID from session
const authUserId = session.user._id;
```

#### 2. Linking MongoDB User to PostgreSQL User

The `authUserId` (MongoDB ObjectId) is used to find or create the corresponding user in PostgreSQL:

```typescript
// Find user in PostgreSQL using MongoDB ID
const user = await db.user.findUnique({
  where: { authUserId },
});

// Or create if doesn't exist (via checkUser helper)
const user = await db.user.upsert({
  where: { authUserId },
  update: {
    email: session.user.email,
    name: session.user.name,
  },
  create: {
    authUserId,
    email: session.user.email,
    name: session.user.name,
  },
});
```

#### 3. Using User Data in Application Logic

Once the PostgreSQL user is retrieved, it's used for all application operations:

```typescript
// Example: Saving a resume
const resume = await db.resume.upsert({
  where: { userId: user.id }, // PostgreSQL user ID
  update: { content },
  create: {
    userId: user.id, // PostgreSQL user ID
    content,
  },
});
```

### Key Files for Authentication

- **`src/app/api/auth/[...nextauth]/options.ts`**: NextAuth configuration
- **`src/app/api/auth/[...nextauth]/route.ts`**: NextAuth API route handler
- **`src/lib/mongodb.ts`**: MongoDB client connection
- **`src/lib/checkUser.ts`**: Helper to sync MongoDB user to PostgreSQL
- **`src/middleware.ts`**: Route protection middleware

## ⚙️ Quick Start

### Prerequisites

- **Node.js** 18+ 
- **MongoDB** (Atlas or local instance)
- **PostgreSQL** database (Neon, Supabase, or self-hosted)
- **VAPI** account with workflow ID and public token
- **Inngest** account for AI agent workflows and background jobs
- **Stripe** account for payment processing (optional, for premium features)
- **Google OAuth** credentials (optional, for Google login)
- **GitHub OAuth** credentials (optional, for GitHub login)
- **Groq API** key (for AI features)
- **OpenAI API** key or **Google Gemini API** key (optional, for additional AI features)

---

### 1️⃣ Install Dependencies

```bash
npm install
```

This will automatically run `prisma generate` after installation (via `postinstall` script).

---

### 2️⃣ Set Up Environment Variables

Create a `.env.local` file in the root directory:

```env
# MongoDB (Authentication Database)
MONGODB_URI=mongodb+srv://<user>:<pass>@cluster0.mongodb.net/interviewx

# NextAuth
NEXTAUTH_SECRET=your_long_random_secret_here
NEXTAUTH_URL=http://localhost:3000

# PostgreSQL (Application Database - Neon, Supabase, etc.)
DATABASE_URL=postgresql://user:password@host:port/database?sslmode=require

# VAPI (Voice AI Interview)
NEXT_PUBLIC_VAPI_WEB_TOKEN=pk_live_xxx
NEXT_PUBLIC_VAPI_WORKFLOW_ID=wf_xxx

# OAuth Providers (Optional)
GOOGLE_CLIENT_ID=your_google_client_id
GOOGLE_CLIENT_SECRET=your_google_client_secret
GITHUB_CLIENT_ID=your_github_client_id
GITHUB_CLIENT_SECRET=your_github_client_secret

# AI Services
GROQ_API_KEY=your_groq_api_key
OPENAI_API_KEY=your_openai_api_key
GOOGLE_GEMINI_API_KEY=your_google_gemini_api_key

# Inngest (Background Jobs & AI Agent)
INNGEST_EVENT_KEY=your_inngest_event_key
INNGEST_SIGNING_KEY=your_inngest_signing_key

# Stripe (Payment Processing)
STRIPE_SECRET_KEY=sk_test_xxx
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_test_xxx
STRIPE_WEBHOOK_SECRET=whsec_xxx
```

**Important**: 
- Generate `NEXTAUTH_SECRET` using: `openssl rand -base64 32`
- For production, set `NEXTAUTH_URL` to your production domain

---

### 3️⃣ Set Up Databases

#### MongoDB Setup

1. Create a MongoDB Atlas account or use a local MongoDB instance
2. Create a database named `interviewx` (or your preferred name)
3. Update `MONGODB_URI` in `.env.local`
4. The MongoDB Adapter will automatically create required collections:
   - `users`
   - `accounts`
   - `sessions`
   - `verification_tokens`

#### PostgreSQL Setup

1. Create a PostgreSQL database (Neon, Supabase, or self-hosted)
2. Update `DATABASE_URL` in `.env.local`
3. Run Prisma migrations:

```bash
npx prisma migrate dev
```

This will create all tables defined in `prisma/schema.prisma`:
- `User`
- `Assessment`
- `Resume`
- `Experience`
- `Education`
- `Skill`
- `Chat`
- `Message`
- `IndustryInsight`

---

### 4️⃣ Run the Development Server

```bash
npm run dev
```

The application will be available at:
➡️ **http://localhost:3000**

## 🔄 Data Flow: Session → MongoDB → PostgreSQL

### Step-by-Step Flow

1. **User Authentication**:
   ```
   User signs in → NextAuth validates → MongoDB stores user → JWT token created
   ```

2. **Session Creation**:
   ```typescript
   // JWT callback in options.ts
   token._id = user._id.toString(); // MongoDB ObjectId
   token.email = user.email;
   token.name = user.name;
   ```

3. **Session Access in Server Actions**:
   ```typescript
   // Any server action
   const session = await getServerSession(authOptions);
   const authUserId = session.user._id; // MongoDB ID
   ```

4. **PostgreSQL User Lookup**:
   ```typescript
   const user = await db.user.findUnique({
     where: { authUserId }, // Links MongoDB → PostgreSQL
   });
   ```

5. **Application Data Operations**:
   ```typescript
   // Use PostgreSQL user ID for all app data
   await db.resume.create({
     data: {
       userId: user.id, // PostgreSQL UUID
       content: "...",
     },
   });
   ```

### Helper Function: `checkUser`

The `src/lib/checkUser.ts` helper automatically syncs MongoDB users to PostgreSQL:

```typescript
export const checkUser = async () => {
  const session = await getServerSession(authOptions);
  const authUserId = session.user._id; // MongoDB ID
  
  // Upsert user in PostgreSQL
  const user = await db.user.upsert({
    where: { authUserId },
    update: {
      email: session.user.email,
      name: session.user.name,
    },
    create: {
      authUserId,
      email: session.user.email,
      name: session.user.name,
    },
  });
  
  return user;
};
```

## 🎯 Summary

**InterviewX** leverages a sophisticated dual-database architecture where:
- **NextAuth** handles authentication and stores user data in **MongoDB**
- User information from the session (`session.user._id`) is extracted and used as a foreign key (`authUserId`) in **PostgreSQL/Prisma**
- This allows seamless integration between authentication (MongoDB) and application data (PostgreSQL)
- All server actions follow the pattern: Extract session → Find PostgreSQL user via `authUserId` → Perform operations

This architecture provides:
- ✅ Secure authentication with multiple providers (Email, Google, GitHub)
- ✅ Scalable application data storage with proper relational modeling
- ✅ Clear separation of concerns between auth and application data
- ✅ Type-safe database operations with Prisma
- ✅ Flexible user profile and career development management

- ✅ Real-time industry insights and salary data
